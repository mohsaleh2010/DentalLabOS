# خطة التنفيذ — DentalLab OS

> مبنية على `DentalLabOS_SaaS_Implementation_Plan_v3.md` (القسم D لترتيب البناء، والقسم A4 لكتالوج الشاشات، والقسم B لنموذج البيانات، والقسم C لسجل الشاشات). تُحدَّث هذه الوثيقة مع نهاية كل مرحلة، والحالة الفعلية في [PROJECT_STATUS.md](../PROJECT_STATUS.md).

## 1. مبادئ التنفيذ

1. **البناء حسب الاعتماد بين الوحدات** وليس حسب الشاشات: لا وحدة قبل الكيانات والقواعد التي تعتمد عليها.
2. **ترتيب كل شاشة** (القسم C4): مواصفات `docs/screens/{ID}.screen.json` ← الكيان والتهيئة ← خدمة Application بقواعد المجال ← API وDTO ← الشاشة ← الاختبارات.
3. **بوابة كل مرحلة**: لا تُعلن مرحلة مكتملة قبل نجاح الاختبارات الآلية + شرط القبول الإضافي في القسم D + مراجعة PR.
4. **الأمن من الخادم**: الصلاحية والعزل يُفحصان على الخادم لكل طلب. الواجهة تُخفي ما لا يُسمح به لتحسين التجربة فقط.
5. **لا أسرار ولا بيانات اعتماد افتراضية** في المستودع، وCI يتحقق من ذلك.
6. **كل PR صغير قابل للمراجعة** ويغطي وحدة واحدة أو جزءًا واضحًا منها.

## 5. طريقة العمل لكل مرحلة

1. فرع لكل مرحلة/وحدة، وPR بقائمة تحقق: مواصفات الشاشات، الاختبارات، تحديث `PROJECT_STATUS.md` و`CHANGELOG.md`.
2. CI أخضر شرط للدمج.
3. مراجعة يدوية للواجهة بالعربية والإنجليزية، والوضع الداكن، وعرض الجوال.
4. بعد الدمج: تحديث هذه الخطة بما تعلمناه وتقدير المرحلة التالية بناءً على السرعة الفعلية.
